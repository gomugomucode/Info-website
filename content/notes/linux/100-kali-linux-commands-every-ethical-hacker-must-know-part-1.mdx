## Tools and Commands

### 1. Web Application Testing

#### Nuclei

Nuclei runs template-based checks against web apps, APIs, cloud services, and network endpoints.

**Defensive use**

* Validate known misconfigurations.
* Check for exposed panels, weak headers, and outdated components.
* Re-test fixes after remediation.

```bash
nuclei -u https://example.com -severity low,medium
```

```bash
nuclei -l live-hosts.txt -tags exposure,misconfig -o nuclei-results.txt
```

**Important note:** Templates can be noisy or intrusive. Review template intent before running scans against production systems.

#### ffuf

ffuf is a fast web fuzzer for discovering directories, files, virtual hosts, and parameters.

**Defensive use**

* Find unintentionally exposed files.
* Check whether admin paths are publicly reachable.
* Validate that removed endpoints are no longer accessible.

```bash
ffuf -u https://example.com/FUZZ -w words.txt
```

```bash
ffuf -u https://example.com/page?FUZZ=test -w params.txt -mc 200,301,302,403
```

**Important note:** Fuzzing creates many requests. Use rate limits, approved scan windows, and non-production targets when possible.

#### Katana

Katana crawls web applications to discover URLs, parameters, forms, and linked assets.

**Defensive use**

* Build an endpoint inventory.
* Identify forgotten routes and exposed files.
* Feed discovered URLs into approved validation tools.

```bash
katana -u https://example.com -depth 2
```

```bash
katana -list live-hosts.txt -jc -o crawled-urls.txt
```

**Important note:** Crawlers may touch sensitive workflows. Exclude logout, payment, destructive, or state-changing paths unless explicitly approved.

### 2. OSINT and DNS Enumeration

#### Amass

Amass maps external assets by combining OSINT, DNS data, and infrastructure relationships.

**Defensive use**

* Build an external attack-surface inventory.
* Find forgotten subdomains.
* Support DNS cleanup and asset ownership review.

```bash
amass enum -passive -d example.com
```

```bash
amass enum -d example.com -o amass-subdomains.txt
```

**Important note:** Confirm domain ownership and scope before treating discovered assets as test targets.

#### subfinder

subfinder quickly discovers subdomains from passive public sources.

**Defensive use**

* Create a first-pass subdomain list.
* Compare public exposure against the asset register.
* Support certificate transparency review.

```bash
subfinder -d example.com -o subdomains.txt
```

```bash
subfinder -dL domains.txt -all -o all-subdomains.txt
```

**Important note:** Passive results can include stale or third-party records. Validate ownership before scanning.

#### httpx

httpx probes hosts to identify live HTTP services, status codes, titles, technologies, and redirects.

**Defensive use**

* Separate live web assets from stale DNS records.
* Capture basic service metadata.
* Prioritize systems for hardening review.

```bash
httpx -l subdomains.txt -title -status-code -tech-detect
```

```bash
httpx -l hosts.txt -ports 80,443,8080,8443 -o live-hosts.txt
```

**Important note:** Fingerprinting is lightweight, but it still creates traffic. Keep target lists scoped and documented.

### 3. Network and Service Discovery

#### naabu

naabu performs fast port discovery and integrates well with modern reconnaissance workflows.

**Defensive use**

* Identify exposed services on approved hosts.
* Validate firewall changes.
* Create a service inventory for remediation planning.

```bash
naabu -host 192.0.2.10 -top-ports 100
```

```bash
naabu -list hosts.txt -p 80,443,8080,8443 -o open-ports.txt
```

**Important note:** Port scanning can trigger alerts and degrade fragile services. Use approved timing and rate limits.

#### enum4linux-ng

enum4linux-ng gathers SMB and Windows-related information from in-scope hosts.

**Defensive use**

* Review SMB shares and access exposure.
* Identify domain, user, and policy information visible to the network.
* Support internal Windows hardening assessments.

```bash
enum4linux-ng -A 192.0.2.10
```

```bash
enum4linux-ng -S -U -P 192.0.2.10 -oJ enum4linux-results
```

**Important note:** SMB enumeration can reveal sensitive internal details. Protect output files and avoid broad scans without approval.

### 4. Traffic Analysis and Authentication Resilience

#### mitmproxy

mitmproxy is an interactive proxy for inspecting HTTP and HTTPS traffic during approved testing.

**Defensive use**

* Review API requests and responses.
* Confirm whether sensitive data is transmitted securely.
* Test web and mobile application behavior in a controlled lab.

```bash
mitmproxy --listen-port 8080
```

```bash
mitmdump -w traffic-flow.mitm
```

**Important note:** Intercepting traffic requires informed consent and careful certificate handling. Never inspect user traffic without authorization.

#### Evilginx2

Evilginx2 is a reverse-proxy framework sometimes used in formal phishing-resilience simulations.

**Defensive use**

* Demonstrate why MFA-resistant controls are needed.
* Train teams to recognize risky login flows.
* Validate detection, reporting, and incident-response procedures in a controlled lab.

```bash
evilginx -p ./phishlets
```

```bash
evilginx -developer
```

**Important note:** This tool can be abused for credential theft. Use only in written, approved awareness exercises with test accounts, isolated domains, and legal oversight.

### 5. Vulnerability Analysis

#### Nuclei Templates

Nuclei templates define the checks that Nuclei runs. Treat templates as code and review them before use.

**Defensive use**

* Select safe checks for a specific technology stack.
* Reduce false positives by choosing relevant templates.
* Build repeatable validation for known internal misconfigurations.

```bash
nuclei -u https://example.com -templates exposures/
```

```bash
nuclei -l live-hosts.txt -tags cve,misconfig -severity low,medium
```

**Important note:** Avoid running unknown templates blindly. Some checks may be intrusive or unsuitable for production.

## Best Practices

* Get written authorization before scanning, probing, fuzzing, or intercepting traffic.
* Log the operator, date, time, target scope, command, and output location.
* Use isolated labs for intrusive tests, fuzzing, authentication simulations, and proxy interception.
* Run tools with least privilege and avoid unnecessary root access.
* Keep target lists narrow and remove out-of-scope systems before testing.
* Avoid production misuse. Prefer passive collection, safe checks, rate limits, and approved maintenance windows.
* Protect reports and scan output because they may reveal sensitive infrastructure details.
