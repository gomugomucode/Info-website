## Tools and Commands

### 1. Web Application Testing

#### SQLmap

SQLmap helps validate SQL injection exposure in authorized web applications and training labs.

**Defensive use**

* Confirm whether a suspected SQL injection finding is reproducible.
* Support remediation by identifying affected parameters.
* Validate fixes after developers patch vulnerable input handling.

```bash
sqlmap -u "https://lab.example/item?id=1" --batch
```

```bash
sqlmap -u "https://lab.example/item?id=1" --risk=1 --level=1 --batch
```

**Important note:** Keep testing scoped to approved systems. Do not use data extraction options on production systems unless the engagement explicitly permits it.

#### Nikto

Nikto checks web servers for common configuration issues, outdated software indicators, and exposed files.

**Defensive use**

* Review server headers and default files.
* Detect risky sample pages or exposed administrative paths.
* Create a remediation checklist for web server hardening.

```bash
nikto -h https://example.com
```

```bash
nikto -h https://example.com -output nikto-report.txt
```

**Important note:** Nikto can produce noisy results. Confirm findings manually before treating them as vulnerabilities.

#### WPScan

WPScan audits WordPress installations for outdated core versions, plugins, themes, and exposed configuration risks.

**Defensive use**

* Inventory WordPress components.
* Identify outdated plugins or themes.
* Support patch planning for site administrators.

```bash
wpscan --url https://example.com
```

```bash
wpscan --url https://example.com --enumerate vp,vt
```

**Important note:** Avoid aggressive enumeration on production sites unless the scan window and rate limits are approved.

### 2. Authentication and Password Auditing

#### Hydra

Hydra tests authentication controls across supported protocols in controlled environments.

**Defensive use**

* Validate lockout policies.
* Check whether test accounts resist weak passwords.
* Confirm monitoring alerts for repeated failed logins.

```bash
hydra -L users.txt -P test-passwords.txt ssh://lab-host
```

```bash
hydra -l testuser -P test-passwords.txt -s 22 ssh://lab-host
```

**Important note:** Use test accounts, rate limits, and lab systems. Never run password testing against third-party services without explicit authorization.

#### John the Ripper

John the Ripper reviews password hash strength during authorized password audits.

**Defensive use**

* Evaluate password policy strength.
* Test sample hashes from controlled lab exercises.
* Help administrators understand weak password risk.

```bash
john --wordlist=wordlist.txt hashes.txt
```

```bash
john --show hashes.txt
```

**Important note:** Store hashes securely and delete temporary audit files after the engagement.

### 3. OSINT and DNS Enumeration

#### theHarvester

theHarvester collects public OSINT such as domains, hosts, and email references from supported public sources.

**Defensive use**

* Understand public exposure for an organization-owned domain.
* Support asset inventory.
* Identify public records that may need cleanup.

```bash
theHarvester -d example.com -b bing
```

```bash
theHarvester -d example.com -b duckduckgo -f harvester-results
```

**Important note:** Public data still needs careful handling. Do not publish personal or sensitive details found during OSINT review.

#### DNSRecon

DNSRecon helps review DNS records, nameservers, and zone-transfer exposure.

**Defensive use**

* Inventory DNS records.
* Check for misconfigured zone transfers.
* Review exposed subdomains and mail records.

```bash
dnsrecon -d example.com
```

```bash
dnsrecon -d example.com -t std
```

**Important note:** Treat DNS findings as configuration evidence. Confirm ownership and business purpose before recommending removal.

### 4. Automated Recon Workflows

#### AutoRecon

AutoRecon automates common service discovery and enumeration workflows for approved hosts.

**Defensive use**

* Standardize lab reconnaissance.
* Collect repeatable evidence for internal assessments.
* Reduce missed service checks during authorized audits.

```bash
autorecon 192.0.2.10
```

```bash
autorecon 192.0.2.0/24 --output ./autorecon-results
```

**Important note:** Automated workflows can generate many requests. Use them only on approved IP ranges.

### 5. Host Monitoring and Process Visibility

#### pspy

pspy monitors Linux processes and scheduled tasks without requiring root privileges.

**Defensive use**

* Observe cron jobs in a lab or owned host.
* Identify unexpected scheduled processes.
* Support incident triage and host diagnostics.

```bash
chmod +x pspy64
./pspy64
```

```bash
./pspy64 -pf
```

**Important note:** Process monitoring may expose sensitive command-line arguments. Protect logs and screenshots.

### 6. Vulnerability Analysis

#### SearchSploit

SearchSploit searches a local copy of Exploit Database references for vulnerability research.

**Defensive use**

* Check whether a product/version has public vulnerability references.
* Support patch prioritization.
* Create context for defensive remediation planning.

```bash
searchsploit apache 2.4
```

```bash
searchsploit --exclude="dos" openssh
```

**Important note:** Search results are research leads. Do not copy or run proof-of-concept code against systems without authorization.

## Best Practices

* Get written authorization before scanning, testing, or monitoring systems.
* Define scope, scan windows, rate limits, and evidence-handling rules before work begins.
* Run intrusive checks in isolated labs whenever possible.
* Use least-privilege accounts for testing and monitoring.
* Log commands, timestamps, targets, and results for auditability.
* Avoid production misuse. Prefer safe validation, configuration review, and remediation support.
* Protect scan outputs because they may reveal sensitive infrastructure details.
