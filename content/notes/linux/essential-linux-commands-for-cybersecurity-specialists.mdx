## Network connection auditing

Modern distributions prefer `ss` over legacy `netstat`. Use it to map listening ports, established sessions, and owning processes.

| Command | Purpose | Example |
| --- | --- | --- |
| `ss -tlnp` | TCP listeners with PID | `ss -tlnp` |
| `ss -tnp` | Established TCP with process | `ss -tnp state established` |
| `ss -uanpe` | UDP sockets with extended info | `ss -uanpe` |
| `lsof -i` | Open network files by process | `lsof -i :22` |
| `tcpdump` | Packet capture for investigation | `tcpdump -i any -nn port 53` |

### Map sockets to processes

<TerminalCommand cmd="ss -tnp state established" />

List processes making outbound connections (exclude loopback):

```bash
ss -tnp | grep -v "127.0.0.1" | awk '{print $6}' | sort | uniq -c | sort -rn
```

### Capture suspicious traffic

```bash
# Save traffic on common C2 ports for offline analysis
tcpdump -i any -w suspicious_traffic.pcap 'port 4444 or port 1337'

# DNS queries in real time
tcpdump -i any -nn port 53
```

For structured port scanning methodology, see [Nmap Scanning & Host Discovery](/notes/networking/nmap-scanning-guide).

## Process and service analysis

Identify unexpected processes, parent-child relationships, and services started outside change windows.

| Command | Purpose | Example |
| --- | --- | --- |
| `ps auxwwf` | Full process list with arguments | `ps auxwwf` |
| `pstree -p` | Process tree with PIDs | `pstree -p` |
| `systemctl list-units` | Running systemd units | `systemctl --type=service --state=running` |
| `lsof -p PID` | Files opened by a process | `lsof -p 1234` |
| `cat /proc/PID/cmdline` | Raw command line | `tr '\0' ' ' < /proc/1234/cmdline` |

### Inspect a suspicious PID

```bash
PID=1234
ps -p "$PID" -o pid,ppid,user,%cpu,%mem,etime,cmd
ls -l /proc/$PID/exe /proc/$PID/cwd 2>/dev/null
lsof -p "$PID" 2>/dev/null | head -20
```

### Service and timer review

```bash
systemctl list-unit-files --type=service --state=enabled
systemctl list-timers --all
```

## Filesystem and permission auditing

Hunt for SUID binaries, world-writable files, and recent changes in sensitive paths.

| Command | Purpose | Example |
| --- | --- | --- |
| `find -perm` | SUID/SGID discovery | `find / -perm -4000 -type f 2>/dev/null` |
| `find -mtime` | Recently modified files | `find /etc -type f -mtime -1` |
| `stat` | Timestamps and ownership | `stat /etc/passwd` |
| `rpm -Va` / `debsums` | Package integrity (distro-specific) | `rpm -Va 2>/dev/null \| grep "^..5"` |

### SUID and world-writable hunt

```bash
# SUID binaries outside common package paths
find / -xdev -type f -perm -4000 2>/dev/null | grep -vE '^/(usr|bin|sbin)/'

# World-writable directories (persistence risk)
find / -xdev -type d -perm -0002 2>/dev/null | head -50
```

### Critical file permissions

```bash
ls -l /etc/passwd /etc/shadow /etc/group /etc/sudoers
# Expected: passwd/group 644, shadow 600 or 000, sudoers 440
```

## User and authentication auditing

Verify accounts, group membership, login history, and privilege escalation paths.

| Command | Purpose | Example |
| --- | --- | --- |
| `id` | Current user groups | `id` |
| `getent passwd` | Local account list | `getent passwd` |
| `last` / `lastb` | Login / failed login history | `last -20` |
| `w` | Currently logged-in users | `w` |
| `grep sudo` | Sudoers and sudo usage | `grep -r '' /etc/sudoers /etc/sudoers.d/ 2>/dev/null` |

### Audit sudo-capable accounts

```bash
getent group sudo wheel admin 2>/dev/null
awk -F: '($3 == 0) {print}' /etc/passwd   # UID 0 accounts
```

## Log analysis and correlation

Correlate authentication events, service failures, and timeline activity.

| Command | Purpose | Example |
| --- | --- | --- |
| `journalctl` | systemd journal (modern distros) | `journalctl -u ssh -S today` |
| `grep auth.log` | Debian/Ubuntu SSH events | `grep "Failed password" /var/log/auth.log` |
| `grep secure` | RHEL/CentOS auth events | `grep "Failed password" /var/log/secure` |
| `ausearch` | auditd events (if enabled) | `ausearch -m USER_LOGIN -ts recent` |

### Failed login summary

```bash
# Top source IPs with failed SSH attempts
grep "Failed password" /var/log/auth.log 2>/dev/null \
  | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head -20

# Successful sudo commands today
journalctl _COMM=sudo --since today --no-pager
```

### Follow a service in real time

<TerminalCommand cmd="journalctl -u ssh -f" />

For Windows host correlation, pair with [Windows Event Log Analysis](/notes/windows/windows-event-log-analysis-advanced-threat-detection-guide).

## Incident response triage

Run this checklist on a potentially compromised host. Collect output to a dedicated incident directory before deeper analysis.

```bash
INCIDENT_DIR="/tmp/incident_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$INCIDENT_DIR"

{
  echo "=== System ==="
  uname -a; uptime; date
  echo "=== Network ==="
  ss -tunap
  echo "=== Processes ==="
  ps auxwwf
  echo "=== Users ==="
  w; last -20
  echo "=== Auth failures ==="
  grep "Failed password" /var/log/auth.log 2>/dev/null | tail -50
  echo "=== SUID files ==="
  find / -xdev -type f -perm -4000 2>/dev/null
} > "$INCIDENT_DIR/triage.txt"

tar czf "${INCIDENT_DIR}.tar.gz" -C /tmp "$(basename "$INCIDENT_DIR")"
```

| Triage step | Command | What to look for |
| --- | --- | --- |
| Baseline identity | `uname -a; hostname; date` | Unexpected hostname or clock skew |
| Live connections | `ss -tunap` | Unknown external IPs, unusual ports |
| Process anomalies | `ps auxwwf` | Misspelled binaries, `/tmp` executables |
| Persistence | `systemctl list-timers --all` | New timers or services |
| Account changes | `last; getent passwd` | New users, odd login times |

## Best practices

* Run read-only triage commands before containment changes when possible.
* Document operator, timestamp, host, and command output path for every audit.
* Prefer `ss` and `journalctl` on systemd hosts; know your distro log paths.
* Scope `find /` and `tcpdump` carefully — they can be noisy and resource-heavy.
* Escalate to memory/disk forensics when live triage shows rootkit indicators.
