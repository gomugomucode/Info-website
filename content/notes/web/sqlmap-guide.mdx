# SQLMap Guide — Authorized SQL Injection Testing

<Callout type="warning" title="Authorized Labs Only">
Run SQLMap only against applications you own or have explicit written permission to test. Never point it at third-party sites without scope approval.
</Callout>

SQLMap automates detection and validation of SQL injection flaws in authorized security assessments. This guide covers installation, safe command patterns, and how findings map to defensive fixes.

## Installation

```bash
# Clone upstream (recommended for latest release)
git clone https://github.com/sqlmapproject/sqlmap.git
cd sqlmap && python sqlmap.py --version

# Debian/Ubuntu package
sudo apt-get install sqlmap

# Verify
sqlmap --version
```

## Command reference

| Flag | Purpose | Example |
| --- | --- | --- |
| `-u` | Target URL | `-u "https://lab.example/item?id=1"` |
| `--data` | POST body | `--data="user=admin&pass=test"` |
| `-p` | Parameter to test | `-p id` |
| `--cookie` | Session cookie | `--cookie="session=abc123"` |
| `--batch` | Non-interactive defaults | always use in CI/lab scripts |
| `--level` / `--risk` | Test depth (1–5 / 1–3) | start low; increase only with approval |
| `--dbs` | List databases | after confirmed injection |
| `--tables` | List tables | `-D dbname --tables` |
| `--technique` | Injection types | `BEUST` (Boolean, Error, Union, Stacked, Time) |

## Authorized testing workflow

### 1. Baseline GET parameter test

```bash
sqlmap -u "https://lab.example/product.php?id=1" --batch --level=1 --risk=1
```

### 2. POST form testing

```bash
sqlmap -u "https://lab.example/login.php" \
  --data="username=test&password=test" \
  --batch --level=1 --risk=1
```

### 3. Test a single parameter

```bash
sqlmap -u "https://lab.example/search.php?q=test&id=1" -p id --batch
```

### 4. Burp request file

```bash
sqlmap -r request.txt --batch
```

Save a raw HTTP request from Burp Suite to `request.txt` and pass it with `-r` / `-m`.

## Defensive mapping

| SQLMap finding | Developer fix |
| --- | --- |
| Boolean-based blind | Parameterized queries; input validation |
| Error-based | Disable verbose SQL errors in production |
| Time-based blind | Query timeouts; WAF/rate limits |
| Union-based | Strict column typing; ORM with bound parameters |
| Stacked queries | Disable multi-statement execution in DB driver |

See [Web Application Security & Hardening](/notes/web/web-security-fundamentals) for prevention patterns.

## Best practices

* Scope targets in a written test plan; exclude production customer data.
* Start with `--level=1 --risk=1`; escalate only when authorized.
* Use `--batch` in repeatable lab scripts; log all commands and output.
* Confirm SQLMap hits manually before reporting — false positives happen.
* Pair with [Nessus](/notes/web/nessus-vulnerability-scanning) for infrastructure-level scanning.
