## 1. Essential HTTP security headers

Security headers instruct browsers to restrict risky behavior.

| HTTP header | Example value | Purpose |
| --- | --- | --- |
| **Strict-Transport-Security** | `max-age=63072000; includeSubDomains` | Force HTTPS |
| **Content-Security-Policy** | `default-src 'self'; script-src 'self'` | Limit script sources (XSS mitigation) |
| **X-Frame-Options** | `DENY` | Block clickjacking via iframes |
| **X-Content-Type-Options** | `nosniff` | Prevent MIME-type sniffing |
| **Referrer-Policy** | `strict-origin-when-cross-origin` | Limit referrer leakage |
| **Permissions-Policy** | `camera=(), microphone=()` | Restrict browser feature APIs |

### Next.js example

```javascript
// next.config.js — security headers
const securityHeaders = [
  { key: "Strict-Transport-Security", value: "max-age=63072000; includeSubDomains" },
  { key: "X-Frame-Options", value: "DENY" },
  { key: "X-Content-Type-Options", value: "nosniff" },
  { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
];
```

## 2. Mitigating cross-site scripting (XSS)

XSS occurs when untrusted input is rendered without encoding.

* **Context-aware output encoding** — HTML-encode user data in templates (`htmlspecialchars`, React JSX auto-escaping).
* **Content Security Policy** — restrict `script-src` to trusted origins; avoid `unsafe-inline` in production.
* **HttpOnly cookies** — prevent JavaScript access to session tokens.
* **Input validation** — allowlist expected formats; reject unexpected markup at the boundary.

## 3. SQL injection prevention

* Use **parameterized queries** / prepared statements — never concatenate user input into SQL.
* Apply **least-privilege DB accounts** — application users should not have `DROP` or `FILE` privileges.
* Log and alert on SQL syntax errors in application logs.

For hands-on authorized validation, see the [SQLmap Guide](/notes/web/sqlmap-guide).

## 4. Authentication and session management

* Enforce MFA for administrative interfaces.
* Rotate session IDs after login; set `Secure` and `HttpOnly` flags on cookies.
* Implement account lockout and rate limiting on login endpoints.
* Store passwords with modern hashing (bcrypt, Argon2) — never plaintext or MD5.

| Phase | Tool / action | Notes |
| --- | --- | --- |
| Discovery | Manual crawl + [Nmap](/notes/networking/nmap-scanning-guide) | Map attack surface in scope |
| Automated scan | [Nessus](/notes/web/nessus-vulnerability-scanning), nuclei | Tune severity filters; confirm manually |
| Manual testing | Burp Suite, browser devtools | Business-logic flaws need human review |
| Reporting | CVSS + reproduction steps | Link to [Bug Bounty Playbook](/notes/security/bug-bounty-playbook) |

## Best practices

* Shift security left — headers and input validation belong in CI, not post-deploy patches.
* Separate staging from production credentials and data.
* Treat scanner output as leads, not confirmed vulnerabilities.
* Document scope and authorization before any intrusive test.
