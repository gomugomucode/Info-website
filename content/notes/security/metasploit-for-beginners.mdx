# Metasploit for Beginners — Authorized Lab Workflow

<Callout type="warning" title="Authorized Testing Only">
Metasploit modules can compromise systems. Use only in isolated lab environments or with explicit written authorization and a defined scope.
</Callout>

Metasploit is an open-source framework for authorized penetration testing. It organizes reconnaissance, exploitation, and post-exploitation capabilities into searchable modules — commonly pre-installed on Kali Linux.

## Module types

| Type | Prefix | Purpose | Example |
| --- | --- | --- | --- |
| **Exploit** | `exploit/` | Target a specific vulnerability | `exploit/windows/smb/ms17_010_eternalblue` |
| **Auxiliary** | `auxiliary/` | Scanning, fuzzing, brute-force helpers | `auxiliary/scanner/http/http_version` |
| **Payload** | `payload/` | Code delivered after exploitation | `payload/windows/x64/meterpreter/reverse_tcp` |
| **Post** | `post/` | Actions on an established session | `post/multi/gather/env` |
| **Encoder** | `encoder/` | Obfuscate payloads | `encoder/x86/shikata_ga_nai` |

## Starting msfconsole

```bash
# Kali / lab install
msfconsole

# Quick version check
msfconsole -q -x 'version; exit'
```

## Core workflow

### 1. Search for modules

```bash
msf6 > search type:exploit platform:windows smb
msf6 > search cve:2021 name:log4j
msf6 > info exploit/linux/http/apache_struts2_content_type_ognl
```

### 2. Configure and run an auxiliary scan

```bash
msf6 > use auxiliary/scanner/portscan/tcp
msf6 > set RHOSTS 192.0.2.10
msf6 > set PORTS 1-1000
msf6 > set THREADS 10
msf6 > run
```

### 3. Exploit module pattern (lab only)

```bash
msf6 > use exploit/multi/handler
msf6 > set payload windows/x64/meterpreter/reverse_tcp
msf6 > set LHOST 192.0.2.5
msf6 > set LPORT 4444
msf6 > run
```

Always set `RHOSTS`, `RPORT`, `LHOST`, and `LPORT` explicitly — never rely on defaults in production-adjacent labs.

## Module selection checklist

| Step | Action |
| --- | --- |
| Recon | Map services with [Nmap](/notes/networking/nmap-scanning-guide) first |
| Search | `search` by CVE, service name, or platform |
| Info | Read `info` — check rank, disclosure date, and side effects |
| Options | `show options` — verify all required fields are set |
| Scope | Confirm target IP is in written authorization |
| Run | `check` when available before `exploit` |

## Defensive detection

Blue teams should monitor for Metasploit indicators:

* Unusual outbound connections to listener ports (4444, 8443, custom `LPORT`)
* Known exploit signatures in IDS/IPS (EternalBlue, Struts OGNL, etc.)
* New services or processes spawned by `psexec`, `wmiexec`, or `meterpreter`
* Spike in failed auth followed by successful lateral movement

See [Blue Team Complete Guide](/notes/security/blue-team-complete-guide) and [Reverse Shells Reference](/notes/security/reverse-shells-cheatsheet).

## Best practices

* Isolate lab targets — no shared credentials with production.
* Prefer `auxiliary` scanners for recon before loading exploits.
* Document module path, options, and timestamp for every run.
* Patch validated CVEs immediately; Metasploit confirms exposure, not business impact.
