Senior Multi-Disciplinary Engineering and Architectural Audit: info.anupambaral.com.np
This report presents a technical, architectural, security, accessibility, performance, and content-strategic audit of the web infrastructure, publishing architecture, and document processing systems of the sub-domain info.anupambaral.com.np and its source code repository gomugomucode/Info-website.1 The target system hosts technical, scientific, and educational resources 3 compiled from converted PDF manuals and lectures authored by Anupam Baral.4
The primary structural goal of this audit is to diagnose parsing errors, security risks, search performance issues, and compilation slow-downs. It also provides an engineering blueprint to transition the repository from its current file-based compilation layout to an enterprise-grade Headless Content Management System (CMS) capable of scaling beyond 500 articles while maintaining fast page speeds and high search rankings.

Static vs. Dynamic Dynamic Execution
The Dynamic Dynamic Route at src/app/posts/[slug]/page.tsx reads files directly from the filesystem during the request cycle without implementing pre-rendering configurations.
Problem
Because the Next.js compiler cannot find a static pre-rendering declaration, it classifies the route as dynamically rendered on demand. This bypasses the build-time HTML cache, forcing the server to read from the filesystem and compile MDX on every request, which increases server load and response times.
Impact
This configuration slows down page delivery, increases server memory usage under high traffic, and prevents the application from being exported as static files for deployment on Edge Delivery Networks.
Severity
High.
Exact Fix

Phase 2: MDX System Review
While MDX offers flexibility by allowing interactive React components inside content pages, using it to store raw text converted from PDF files introduces several rendering and build issues.
Diagnostic Analysis of Conversion Failures
The conversion of PDF lectures and manuals to MDX files has introduced several formatting issues:
Broken Tables: Many tables lack closing XML tags, causing the parser to fail. This throws compilation exceptions like Expected a closing tag for &lt;...&gt; or crashes the browser rendering engine entirely.
JSX Syntax Injection Failures: The MDX compiler treats standard programming notations, such as &lt;T&gt; generic syntax, as JSX tags. Unescaped characters in technical explanations—such as raw &lt;, &gt;, or {—will crash the Next.js build engine with parsing errors.
Formatting and Character Degradation: Paragraphs extracted from PDFs often retain line-end hyphens, splitting words across lines and introducing invalid whitespace (e.g., con- \n troller is parsed as two separate tokens).
Missing Heading Hierarchies: Heading levels are frequently skipped (e.g., jumping from an H1 layout directly to H4). This confuses assistive technologies and breaks dynamic Table of Contents components.
Component Hydration Mismatches: Dynamically calculated parameters, such as raw date parsers or local time formatters inside MDX components, run differently on the client browser than they do during server-side pre-rendering, resulting in hydration errors.

Phase 8: Accessibility Audit
An accessibility review against the WCAG 2.2 AA standard identified several interface issues that prevent screen readers and assistive technologies from navigating the site effectively.
Accessibility Deficiencies
Insufficient Contrast Ratios: Many dark-mode text colors, code comments, and footer links fall below the WCAG-required 4.5:1 contrast ratio, making them difficult to read for visually impaired users.
Incomplete Keyboard Navigation: The mobile menu and interactive elements lack visible focus indicators, making tab-key navigation difficult for keyboard-only users.
Missing Interactive Labels: Custom icon buttons and code-copy utilities lack ARIA labels, meaning screen readers cannot announce their purpose.
Skipped Heading Hierarchies: Heading levels skip from H1 directly to H3, which disrupts the logical reading order for screen reader navigation.
