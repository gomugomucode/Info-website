Phase 2: Codebase Audit and Gap Analysis
A comprehensive technical audit of the gomugomucode/Info-website repository (deployed at info.anupambaral.com.np) highlights several limitations11. Currently, the site operates primarily as a personal portfolio rather than an enterprise-grade developer learning platform11.
Repository Layout and File Index
The codebase is built on a standard Next.js directory layout11. However, it lacks the modular design needed to scale up to a larger knowledge platform.

Technical and Architectural Audit
Component Architecture: The frontend uses standard Tailwind CSS UI components. However, it lacks interactive elements like custom navigation drawers, accessible focus controls, or dynamic canvas displays.
Content Architecture: Technical articles are loaded via standard client-side scripts from external platforms (such as Medium)6. This limits options for deep internal linking, code-block syntax highlighting, or interactive step-by-step navigation.
SEO Infrastructure: The site lacks a centralized metadata configuration. It is missing clean canonical links, responsive open graph images, and specialized structured schemas (like Course, TechArticle, or FAQPage) needed to rank well in search engine results13.
Technical Debt: There is no database or caching layer to support interactive user features. Hardcoded static arrays make it difficult to scale the platform.
Performance Metrics: The site has fast initial load times, but performance drops when loading heavy external scripts. Unoptimized image loading and unbuffered font transitions can trigger layout shifts (CLS) on slower connections13.
Accessibility (WCAG 2.1 AA Compliance): The interactive elements are missing descriptive ARIA labels, focus-state outlines, and keyboard navigation support.
Mobile Responsiveness: The desktop layouts scale down, but the interface lacks a dedicated touch-friendly mobile menu.
Internal Linking: The portfolio structure is relatively flat, offering few internal link paths between related technical resources or articles14.
Search Experience: The platform lacks an internal search tool, making it difficult for users to search across articles, cheatsheets, or labs.

Structural Publishing Guidelines
The BLUF Formatting Pattern: Begin technical articles with a concise summary paragraph of 40 to 60 words16. This helps readers quickly grasp the key takeaway and makes the content highly extractable for AI search engine citations15.
Code Annotations: Include explicit syntax highlights, clear file paths, and detailed explanations of system commands.
Internal Linking Protocols: Related articles and cheatsheets must be linked inline to establish a clear content hierarchy, helping users find relevant topics easily.
